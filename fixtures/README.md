# Fixtures

Lessons, courses and inputs that the test suites, the demonstrations and a fresh checkout rely on. When
you open Studium from a checkout, this folder is the default lessons folder (VS Code `studium.bundlesRoot`,
`BUNDLES_ROOT="$PWD/fixtures"` for the servers). Most lessons are in French.

| | |
|---|---|
| Status | **maintained**: changing a fixture can break a test elsewhere |
| Run | point a surface at this folder, for example `BUNDLES_ROOT="$PWD/fixtures"` |
| Tests | `.venv/bin/python -m pytest fixtures/<name>` where a fixture has its own tests; the others are read by the package, service and extension tests |

For examples meant to be read and copied, see [`examples/`](../examples/README.md).

## Courses and inputs

| Fixture | Content | Used by |
|---|---|---|
| `courses/decay-course.json` | a course manifest chaining the capsule demos with prerequisites | the lesson server's `GET /courses`, the dashboard's course progress |
| `capsule-demo/` | an ASB task card and script for a light first-order decay fit | run, trust and attestation tests (session host, VS Code drivers) |
| `m1/sample-corpus/` | a sample PDF, BibTeX file and DOI list | the ingest service tests |
| `m2/abs_capsule_minimal/` | a minimal ASB capsule (RO-Crate metadata, task card) | ingest, planner and scene-synth capsule tests |

`fixtures/data/` may appear after running a surface against this folder: it is learner state, ignored by
git, and safe to delete.

## Add a fixture

Put a lesson in `<name>/lesson.json`, then lint and validate it:

```bash
node tools/bundle_lint.mjs fixtures/<name>/lesson.json
node_modules/.pnpm/node_modules/.bin/tsx tools/bundle_validate.ts fixtures/<name>/lesson.json
```

The [lesson bundle reference](../docs/reference/lesson-bundle.md) describes the format.
